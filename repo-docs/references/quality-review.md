| 检查问题 | 从指南得到的答案 |
| --- | --- |
| 主路径是什么 | 一个敏感 MCP 工具请求从本机待批准到一次执行 |

## 可证伪性与后续问题

证伪检查：若改变路径仍能复用批准，或连接器先执行再登记请求账本，则单次精确批准模型失效。先复查连接器回归和批准对象摘要，再讨论端到端保证。

读者下一问：OAuth 撤销与已经开始的工具操作怎样衔接？需另读 `cloud/auth-store.mjs`、`auth-transactions.mjs` 与事务测试，本指南不声称撤销能追回已执行效果。

## 剩余风险

不逐项覆盖 OAuth 所有事务、Windows 安装/凭据轮换、全部文件 ACL 分支和容器生命周期；没有重新验收线上网关、Docker 镜像或已安装副本。 文档结构验证和静态站点构建不能替代运行时、平台接线或生产验证；SOURCE 链接需在克隆/代码托管视图使用。README 原有丰富说明保留，root AGENTS 统一规则，CLAUDE 仅作路由。
